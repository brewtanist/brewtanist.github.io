# Brewtanist — ร่างเว็บใหม่

เริ่มที่ [ตัวอย่างล่าสุดที่ผ่านการตรวจ](LATEST.md) โดยเลือก **เปิดข้อมูลล่าสุดจาก GitHub** เพื่อไม่ให้ร่างเก่าที่เก็บในเบราว์เซอร์ทับข้อความหรือรูปใหม่

## แก้แบบเก็บออนไลน์

เปิด [Pages CMS](https://app.pagescms.org/) เลือกองค์กร `brewtanist` → repo `brewtanist.github.io` → branch `preview/brewtanist-lab-20261108` ห้ามเลือก `main` สำหรับงานร่าง

- **01 · ข้อความหน้าแรกและคำอธิบายกาแฟ**: หัวเรื่อง ข้อความแนะนำ และคำอธิบายทั้งสาม Blend
- **02 · รูปและข้อมูลสินค้า**: เลือกรูป เปลี่ยนชื่อ ระดับคั่ว Tasting notes สีพื้น ราคา ขนาด การบด แหล่งปลูก ลิงก์ Shopee และกฎช่วยเลือกกาแฟ
- **คลังรูป**: ใช้โฟลเดอร์ `prototype/media` เท่านั้น มีสำเนาภาพทั้งสาม Blend ให้แล้ว เปลี่ยนได้โดยไม่แตะรูปในเว็บหลัก ใช้ JPG/PNG/WebP ไม่เกิน 8 MB รูปต้องเป็นของร้านหรือได้รับสิทธิ์แล้ว

ใช้ปุ่มซ่อนแทนการลบสินค้า ตอนนี้รองรับรหัสเดิมสามรายการ ข้อมูลที่ยังไม่ทราบให้เว้นว่าง ห้ามกรอกข้อมูลลูกค้า รหัสผ่าน หรือ Token เพราะ repository และร่างเป็นสาธารณะ

เมื่อ Save ข้อมูลจะเก็บใน GitHub จากนั้นระบบตรวจรูปแบบข้อมูล สร้างตัวอย่าง และทดสอบในเบราว์เซอร์ ถ้าผ่านจะอัปเดต LATEST.md ถ้าไม่ผ่าน ลิงก์ยังอยู่ที่รุ่นที่ผ่านก่อนหน้า ดูข้อความผิดพลาดได้ใน GitHub Actions

การอัปโหลดรูปอย่างเดียวไม่ได้เปลี่ยนรูปสินค้า ต้องเลือกไฟล์นั้นในช่องรูปสินค้าแล้ว Save อีกครั้ง อย่าลบรูปที่ยังใช้อยู่ ระบบจะไม่เผยแพร่รอบใหม่เมื่ออ้างถึงรูปที่หาย

## ทดลองเฉพาะในเครื่อง

Content Studio ภายในตัวอย่างใช้ทดลองข้อความ รูป และส่งออก JSON/HTML เท่านั้น **ไม่บันทึกเข้า GitHub** ร่างในเครื่องเก็บแยกจาก Pages CMS การเปิดข้อมูลจาก GitHub ไม่ลบร่างในเครื่องทิ้ง

## สถานะการทดสอบและข้อจำกัด

ทดสอบไฟล์ข้อมูล → builder → ตัวอย่างใน Chromium แล้ว รวมการเปลี่ยนรูปจริงด้วยไฟล์ทดสอบที่ลบออกหลังทดสอบ ไม่มีราคาทดสอบหลงเหลือในร่างจริง ยังไม่ได้ทดสอบ OAuth / Save ใน Pages CMS ด้วยบัญชีเจ้าของ และยังไม่ได้ทดสอบ iPhone/Safari จริง

สาขาร่างไม่ใช่ระบบล็อกสิทธิ์ Branch protection ยังไม่ได้ตั้ง คง PR เป็น Draft และห้าม Merge ทั้งชุดเพื่อแค่ดูตัวอย่าง เพราะ .pages.yml ของร่างต่างจากเว็บหลักโดยตั้งใจ

## ก่อนขึ้นเว็บจริง

ต้องตรวจรายละเอียดสินค้าปัจจุบันและกฎแนะนำ เลือก Hosting สำหรับแคตตาล็อก ตรวจการแก้ผ่านบัญชีเจ้าของ และกำหนดขั้นอนุมัติเผยแพร่ ไม่มี Checkout การรับเงิน การซิงก์สต็อก หรือ Analytics ในรุ่นนี้

ภาษาใช้แนวที่อนุมัติแล้ว: พูดเรื่องกาแฟตรง ๆ ไม่อ้างความแม่นยำ ไม่สร้างความเร่งด่วน ราคา หรือสต็อกขึ้นเอง
